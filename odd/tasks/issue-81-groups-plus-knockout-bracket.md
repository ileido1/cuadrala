# Issue #81 — GROUPS_PLUS_KNOCKOUT bracket view

Branch: `feat/issue-81-groups-plus-knockout-bracket`. API runner: `npm test` (vitest) in `services/api/`. Mobile runner: `flutter test` in `apps/mobile/`.

## Specs

- **S1**: `GET /tournaments/:id/bracket` must support `GROUPS_PLUS_KNOCKOUT` once its knockout phase has been materialized (i.e. `AdvanceGroupsPlusKnockoutUseCase` has resolved semifinals — see `services/api/src/application/use_cases/advance_groups_plus_knockout.use_case.ts:112-175`). The response must reuse the existing `TournamentBracketDTO`/`BracketRoundDTO`/`BracketMatchDTO` shape (`get_tournament_bracket.use_case.ts:13-43`) with exactly the two knockout-stage rounds ("Semifinales", "Final") — built from the real stored schedule payload (`SCHEDULE.payload.rounds` filtered to `stage === 'KNOCKOUT'`, per `services/api/src/domain/groups_plus_knockout/groups_plus_knockout_schedule_generator.ts:28-34,146-181`) and real match state (same `TournamentMatchResultRepository`/`listTournamentMatchStatesSV` pattern already used at `get_tournament_bracket.use_case.ts:147-159`), **not** by calling `generateSingleEliminationScheduleSV` — that generator is for a different format and would produce the wrong structure. `bracketSize` for this format is fixed at 4 in v1 (`GROUPS_PLUS_KNOCKOUT_DEFAULT_PARAMETERS`), `totalRounds` is 2.
- **S2**: Before the knockout phase exists for a `GROUPS_PLUS_KNOCKOUT` tournament (schedule stored but semifinals not yet materialized, or no schedule stored at all), `GET /bracket` must throw a **distinct, accurate** `AppError` — not the current `'FORMATO_NO_SOPORTADO'` / "Bracket disponible solo para torneos SINGLE_ELIMINATION." message, since that's factually wrong for this format. Use a new error code, e.g. `'CUADRO_NO_GENERADO'`, 400, with an accurate Spanish message (e.g. "El cuadro final todavía no fue generado para este torneo."). Every other non-`SINGLE_ELIMINATION`, non-`GROUPS_PLUS_KNOCKOUT` format (`ROUND_ROBIN`, `AMERICANO`, etc.) must keep throwing the existing `'FORMATO_NO_SOPORTADO'` unchanged — do not widen that branch.
- **S3**: The "Final" round's `playerA`/`playerB` slots are allowed to render as `null` ("TBD") when the semifinal winners haven't been resolved/advanced into it yet — do **not** invent winner-propagation logic as part of this task. This mirrors the existing single-elimination endpoint's own philosophy ("sin inventar jugadores" per `get_tournament_bracket.use_case.ts:166-185`). If you find during implementation that nothing in the codebase ever populates the Final's slots from semifinal results, that is a separate, pre-existing gap outside this issue's scope ("no tiene vista de bracket") — note it in your handoff, do not try to fix it here.
- **S4**: Mobile: once the API confirms the knockout phase exists (S1's 200 response), a player or organizer on a `GROUPS_PLUS_KNOCKOUT` tournament must be able to reach the existing `BracketScreen` (`apps/mobile/lib/src/features/tournaments/presentation/screens/bracket_screen.dart`) unchanged — reuse it as-is, since the DTO shape is identical to `SINGLE_ELIMINATION`'s. Before the knockout phase exists, do not offer bracket access for this format (today's organizer standings-only view, `_OrganizerStandingsContent` in `org_bracket_tab.dart`, already behaves this way and must keep doing so).
- **S5**: Fix the hardcoded empty-state copy in `BracketScreen` (`bracket_screen.dart` around lines 67-74) that says "Este torneo es round robin: seguí la posición en la tabla." — that message is wrong when the trigger is a `GROUPS_PLUS_KNOCKOUT` tournament whose knockout phase isn't generated yet (post-S2, the API now returns a distinct `'CUADRO_NO_GENERADO'` error code for that case). Branch the empty-state message on the actual error code returned, with accurate copy per case.
- **S6**: The player tab's "Ver cuadro" button (`player_tabs.dart:356-368`, `showBracketButton` defaulting to `true` at `player_tabs.dart:287,293`) must not be offered unconditionally for every format. Gate it so a `GROUPS_PLUS_KNOCKOUT` tournament without a generated knockout phase does not present a bracket button that is known to fail. Decide the simplest correct mechanism given what's already wired (e.g. reuse the existing tournament/schedule data the tab already has to know whether the format even has a bracket concept) — this is an implementation-detail decision, not a product one; use your judgment reading the surrounding code.
